# 采集与时间对齐

## 批量获取

- 写明账号、请求数量、采集时间和排序。用视频 ID 去重，依据实际发布时间倒排。置顶或接口排序异常时，多取一页或足够条目确认截点。只计成功取得的资产。发布配文、平台字幕、音轨、画面文字和播放快照分别记录。
- 优先现有可用工具。TikTok 可先试 `yt-dlp --ignore-config --flat-playlist --dump-single-json --playlist-end 60 PROFILE_URL`，60 仅是请求最新 50 条时探查截点的起始量。逐条读取语言轨键和媒体格式。中文轨可能是 `cmn-Hans-CN`，也可能是 `zh-Hans`、`zh-CN` 或其他标记。按实际键精确选择。示例 `yt-dlp --skip-download --write-subs --write-auto-subs --sub-langs 'cmn-Hans-CN' VIDEO_URL`。
- 下载媒体后用 `ffprobe` 确认音轨和时长。格式声明有音频时，实际文件仍需检查。缺音轨时换同一视频的可用格式。Hypit、本地 Whisper 或其他可用转录工具均可。提取音频可用 `ffmpeg -i INPUT -vn -ac 1 -ar 16000 OUTPUT.wav`。
- 对照最后一个字幕结束时间和媒体长度，抽查尾部是否还有口播。补录尾部时记录偏移，把结果换算为原视频时间并消除重叠。口播和字幕都有自动误识时，优先核对高影响数字、否定词、产品名、说话人和争议声明。来源不充分就标待核。
- 取不到指定来源时，记录已尝试入口、实际数量和覆盖范围。镜像、标题和配文可以提供线索。以其作为唯一证据时如实限定分析。批量任务保持中间结果可复用，逐条重试失败项。

## 逐帧交付

理解用户要的是逐帧脚本对齐、画面文字核查，还是逐帧画面观察。脚本对齐可以覆盖每帧，画面 OCR 抽样仅支持抽中的帧。两者都按实际覆盖在报告里列数量。

`scripts/align_captions.py` 可从本地 VTT 或 SRT 输出带片段 ID 的 JSON。提供本地视频时，它用 FFprobe 的逐帧呈现时间与字幕对齐，并额外输出压缩的逐帧 CSV。需要 Python 3.9 或更高版本。对齐媒体时需要 FFprobe。

```bash
python3 scripts/align_captions.py speech.vtt --video clip.mp4 --video-id V01 --output-dir clip-review
```

- `captions_timed.json` 保留源字幕和区间，可作为完整报告时间轴的输入。时间从媒体起点计，帧号从零计。区间开始含边界，结束不含边界。
- `frame_script_alignment.csv.gz` 含每帧时间和当前字幕 ID，重叠时保留多个 ID。文本与帧对齐只说明区间相交。要分析画面文本，还需在对应 PTS 的画面做 OCR 或检查原图。
- 使用抽样时记录步长、实际时间点、有效样本。OCR 可能读到画中画或标题。对比时保留 OCR、字幕、音轨各自来源和误差。仅在真实观察支持时指出画面文字何时补足口播承诺。
- 对于不能测得的音频指标，保留空值或标待核。字幕空窗可记录为字幕现象。语速按已识别口播时长统计并说明单位。没有可靠语音区间时只报字幕密度。
